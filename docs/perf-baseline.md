# Performance Baseline (Pilot)

> Snapshot of the latency / throughput / availability measurements that
> establish the floor for PSMS pilot. The numbers in this file are
> **measurements**, not targets. Targets live in `docs/specs/performance.md`
> (PRF-01 — PRF-10) and may not be relaxed without an ADR.

## How this file is updated

This is a living document. The pre-pilot baseline is captured once on a
pinned commit; thereafter the CI job `perf-baseline` (Phase 6+) emits
the same measurements on every release tag and appends a row to each
table below. Regressions of more than **10%** against the baseline
fail the release gate.

## Reference dataset

200 users × 1 active placement each, with 12 hours-logs per placement
in mixed states (PENDING / APPROVED / REJECTED), generated by the seed
script `pnpm db:seed --scale=pilot`. The seed is deterministic — the
same git commit produces the same fixture.

## Known shortcuts (to revisit before pilot graduation)

- Single API process — no cluster, no horizontal scaling. Fine for
  pilot (≤ 250 users), revisit when concurrent active users exceeds
  200 sustained or PRF-01 / PRF-02 baseline degrades.
- The PRC-09 dashboard query is ad-hoc SQL; if PRF-07 baseline lands
  near the budget ceiling, materialise to a `dashboard_snapshot` table
  refreshed every 60 s.
- No CDN. Static assets are served by nginx in the same container as
  the SPA shell. Acceptable for an in-college pilot.
- Backups go to a single bucket. Cross-region replication is a Phase 2
  problem (it's listed in the risks table in PLAN.md).

## How to re-run the baseline

```bash
# 1. Seed the pilot dataset on a clean DB.
pnpm db:reset
pnpm db:seed -- --scale=pilot

# 2. Start the stack in production-equivalent mode.
docker compose -f docker-compose.prod.yml --env-file .env.perf up -d

# 3. Run the perf suite.
pnpm exec k6 run tests/perf/read-endpoints.js
pnpm exec k6 run tests/perf/write-endpoints.js
pnpm exec k6 run tests/perf/concurrent-users.js

# 4. Fill the baseline columns in this file and commit on the
#    `perf/baseline-YYYY-MM` branch.
```

The k6 scripts under `tests/perf/` are tracked in this repo; the
`.env.perf` file is *not* and must be sourced from the host secret
store (use the same shape as `.env.example`).
